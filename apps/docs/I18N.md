# Docs site languages (EN / RU)

The site is fully bilingual. Every page exists in English and Russian; TypeScript fails the
build if a Russian text is missing.

## How it works

- **URLs.** English pages are unprefixed (`#/charts/line-chart`), Russian pages live under
  `#/ru` (`#/ru/charts/line-chart`, `#/ru` for the home page). Section anchors stay the same
  in both languages (`#/ru/charts/line-chart#props`).
- **Choosing the language.** A `#/ru/…` URL is always Russian. An unprefixed URL follows the
  visitor's preference — the EN/RU switch in the header (stored in `localStorage` under
  `jc-docs-lang`), otherwise the browser language (`ru*` and `kk*` → Russian, anything else →
  English) — and is rewritten to `#/ru/…` in place when that preference is Russian. Existing
  English links therefore keep working. After a switch, back/forward show pages in the chosen
  language.
- **Where the language lives.** The router (`src/lib/router.tsx`) parses the prefix; the page
  language is `useLocation().lang`. It drives `<html lang>`, `document.title`, the meta
  description and the site-wide `<ChartProvider locale={lang}>` in `App.tsx`, so numbers and
  dates on every live chart are localised too.
- **Files.**
  - `src/i18n/lang.ts` — `Lang`, `LANGS`, `L<T>` (a value per language), preference and
    browser detection.
  - `src/i18n/en.ts` — shared UI strings (top bar, sidebar filter, theme switch, navigation, page
    names, example/code panels, tables, error messages, aria-labels). Its shape is the `Messages` type.
  - `src/i18n/ru.ts` — the same keys in Russian, typed as `Messages`.
  - `src/i18n/index.ts` — `useLang()`, `useT()` (shared strings), `useText(TEXT)` (page-local
    texts), `ruPlural()`.

## Writing content

**Shared UI string** (used by more than one component): add the key to `en.ts`; TypeScript
then reports it missing in `ru.ts`. Read it with `const t = useT(); t.section.key`.

**Page prose** lives next to the page markup, one markup tree for both languages:

```tsx
interface PageText {
  lead: string;
  intro: ReactNode;
}

const TEXT: L<PageText> = {
  en: {
    lead: '…',
    intro: (
      <>
        Use <code>series</code> …
      </>
    ),
  },
  ru: {
    lead: '…',
    intro: (
      <>
        Используйте <code>series</code> …
      </>
    ),
  },
};

export function MyPage() {
  const ui = useT();
  const t = useText(TEXT);
  return <PageHeader eyebrow={ui.nav.guides} title={ui.pages.myPage} lead={t.lead} />;
}
```

**Data tables** (props, API entries, tokens) put both languages on each row:
`description: { en: '…', ru: '…' }`. In plain strings, backticks become inline code. A prop
`default` is a plain string when it is code (`'vertical'`, `true`) and `{ en, ru }` when it is
prose (`{ en: 'per chart', ru: 'зависит от диаграммы' }`).

## Adding a page

1. Add its name to `pages` in `src/i18n/en.ts` and `src/i18n/ru.ts`.
2. Create `src/pages/MyPage.tsx` with a `TEXT: L<…>` object as above.
3. Register the language-neutral path in `src/routes.tsx` (title from `t.pages.myPage`) and,
   if it belongs in the sidebar, in `src/nav.ts`.
4. Use `<Link to="/my-page">` for internal links — it adds the current language prefix. Never
   hard-code `#/…` hrefs.

## Adding a chart

1. Put its live examples in `src/examples/<slug>/*.tsx`. Example code is shown verbatim in the
   code panels, so it is written once (in English) and not translated; on the Russian site the
   preview still formats numbers and dates in Russian through the site's `ChartProvider`.
2. Describe the page in `src/docs/charts/<slug>.tsx` as a `ChartDoc`: `title`, `summary`,
   `description`, example `title`/`description`, `sectionNotes`, keyboard actions, prop group
   `title`/`note` and prop descriptions are all `{ en, ru }`. Reuse `src/docs/props.tsx` and
   `src/docs/keyboard.ts` for shared tables. `src/docs/charts/line-chart.tsx` is a good
   template.
3. List it in `src/docs/charts/index.ts`.
4. Add its “When to use it” guidance (`good` situations and what to pick `instead`, both
   languages) to `src/docs/when-to-use.ts`. The sidebar icon comes from `CHART_ICONS` in
   `src/nav.ts`.

## Conventions for Russian

Write as a senior frontend engineer would for ru.react.dev: short sentences, imperative mood
for instructions, «ёлочки» for quotes, code identifiers untouched. Terms used across the site:
диаграмма, ряд (данных), ось X / ось значений, подсказка (tooltip), легенда, перекрестие,
масштабирование, панорамирование, выделение диапазона (brush), тема, рендерер, пропсы / проп,
прореживание, опорная линия, примитив, локаль, токен, скринридер, «нет данных».

## Left in English on purpose

- Example source code and the texts it renders (it is the real code shown in the code panels).
- `CHANGELOG.md` (the Russian page shows a note above it).
- Benchmark data identifiers that have no translation (unknown scenario names fall back to the
  English text from `benchmarks/*.json`).

## Adding another language

Add it to `Lang` and `LANGS` in `src/i18n/lang.ts` and to `same()`; TypeScript then lists every
`L<…>` value and dictionary that needs a translation. Add its dictionary to `MESSAGES` in
`src/i18n/index.ts`. The router picks up the `#/<lang>` prefix from `LANGS`; extend
`browserLang()` for detection.
