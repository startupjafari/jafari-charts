# Docs site languages (EN / RU / KK)

The site is fully trilingual. Every page exists in English, Russian and Kazakh (Cyrillic);
TypeScript fails the build if a Russian or Kazakh text is missing.

## How it works

- **URLs.** English pages are unprefixed (`#/charts/line-chart`), Russian pages live under
  `#/ru` (`#/ru/charts/line-chart`, `#/ru` for the home page) and Kazakh pages under `#/kk`
  (`#/kk/charts/line-chart`, `#/kk`). Section anchors stay the same in every language
  (`#/kk/charts/line-chart#props`).
- **Choosing the language.** A `#/ru/…` URL is always Russian, a `#/kk/…` URL always Kazakh. An
  unprefixed URL follows the visitor's preference — the language select in the header
  (StudentHub's `Select`: flag + endonym in StudentHub's order Русский, Қазақша, English; only
  the flag on phones, the full select in the phone drawer; stored in `localStorage` under
  `jc-docs-lang`), otherwise the browser language (the first entry of `navigator.languages` that is `kk*` or `kz*` → Kazakh,
  `ru*` → Russian, `en*` → English; nothing matching → English) — and is rewritten to
  `#/ru/…` or `#/kk/…` in place when that preference is not English. Existing English links
  therefore keep working. After a switch, back/forward show pages in the chosen language.
- **Where the language lives.** The router (`src/lib/router.tsx`) parses the prefix; the page
  language is `useLocation().lang`. It drives `<html lang>`, `document.title`, the meta
  description and the site-wide `<ChartProvider locale={lang}>` in `App.tsx`, so numbers and
  dates on every live chart are localised too. The chart library ships `kk` locale data
  (number and date formats and its built-in texts such as «Деректер жоқ»), so Kazakh pages pass
  `locale="kk"` like Russian pages pass `locale="ru"`; no fallback is needed.
- **Files.**
  - `src/i18n/lang.ts` — `Lang`, `LANGS`, `L<T>` (a value per language), preference and
    browser detection.
  - `src/i18n/en.ts` — shared UI strings (top bar, sidebar filter, theme switch, navigation, page
    names, example/code panels, tables, error messages, aria-labels). Its shape is the `Messages` type.
  - `src/i18n/ru.ts`, `src/i18n/kk.ts` — the same keys in Russian and Kazakh, typed as
    `Messages`. `langName` is the language's own name, shown in the language select.
  - `src/i18n/index.ts` — `useLang()`, `useT()` (shared strings), `useText(TEXT)` (page-local
    texts), `ruPlural()` and `kkPlural()`.

## Writing content

**Shared UI string** (used by more than one component): add the key to `en.ts`; TypeScript
then reports it missing in `ru.ts` and `kk.ts`. Read it with `const t = useT(); t.section.key`.

**Page prose** lives next to the page markup, one markup tree for both languages:

```tsx
interface PageText {
  lead: string;
  intro: ReactNode;
}

const TEXT: L<PageText> = {
  en: {
    lead: '…',
    intro: (
      <>
        Use <code>series</code> …
      </>
    ),
  },
  ru: {
    lead: '…',
    intro: (
      <>
        Используйте <code>series</code> …
      </>
    ),
  },
  kk: {
    lead: '…',
    intro: (
      <>
        <code>series</code> пропын пайдаланыңыз …
      </>
    ),
  },
};

export function MyPage() {
  const ui = useT();
  const t = useText(TEXT);
  return <PageHeader eyebrow={ui.nav.guides} title={ui.pages.myPage} lead={t.lead} />;
}
```

**Data tables** (props, API entries, tokens) put every language on each row:
`description: { en: '…', ru: '…', kk: '…' }`. In plain strings, backticks become inline code. A
prop `default` is a plain string when it is code (`'vertical'`, `true`) and `{ en, ru, kk }` when
it is prose (`{ en: 'per chart', ru: 'зависит от диаграммы', kk: 'диаграммаға байланысты' }`).

**Plurals.** Russian needs three forms: `ruPlural(n, ['тип', 'типа', 'типов'])`. Kazakh nouns
keep the singular after a numeral («5 диаграмма», «22 түрі»), so `kkPlural(n, 'диаграмма')`
returns the word as is; pass a pair `[one, other]` for the rare text that differs — it is chosen
with `Intl.PluralRules('kk')`.

## Adding a page

1. Add its name to `pages` in `src/i18n/en.ts`, `src/i18n/ru.ts` and `src/i18n/kk.ts`.
2. Create `src/pages/MyPage.tsx` with a `TEXT: L<…>` object as above.
3. Register the language-neutral path in `src/routes.tsx` (title from `t.pages.myPage`) and,
   if it belongs in the sidebar, in `src/nav.ts`.
4. Use `<Link to="/my-page">` for internal links — it adds the current language prefix. Never
   hard-code `#/…` hrefs.

## Adding a chart

1. Put its live examples in `src/examples/<slug>/*.tsx`. Example code is shown verbatim in the
   code panels, so it is written once (in English) and not translated; on the Russian and
   Kazakh sites the preview still formats numbers and dates in that language through the
   site's `ChartProvider`.
2. Describe the page in `src/docs/charts/<slug>.tsx` as a `ChartDoc`: `title`, `summary`,
   `description`, example `title`/`description`, `sectionNotes`, keyboard actions, prop group
   `title`/`note` and prop descriptions are all `{ en, ru, kk }`. Reuse `src/docs/props.tsx` and
   `src/docs/keyboard.ts` for shared tables. `src/docs/charts/line-chart.tsx` is a good
   template.
3. List it in `src/docs/charts/index.ts`.
4. Add its “When to use it” guidance (`good` situations and what to pick `instead`, both
   languages) to `src/docs/when-to-use.ts`. The sidebar icon comes from `CHART_ICONS` in
   `src/nav.ts`.

## Conventions for Russian

Write as a senior frontend engineer would for ru.react.dev: short sentences, imperative mood
for instructions, «ёлочки» for quotes, code identifiers untouched. Terms used across the site:
диаграмма, ряд (данных), ось X / ось значений, подсказка (tooltip), легенда, перекрестие,
масштабирование, панорамирование, выделение диапазона (brush), тема, рендерер, пропсы / проп,
прореживание, опорная линия, примитив, локаль, токен, скринридер, «нет данных».

## Conventions for Kazakh

Kazakh in Cyrillic, written as clear technical prose for working engineers: short sentences,
instructions in the polite imperative (`…пайдаланыңыз`, `…қосыңыз`), «ёлочки» for quotes, code
identifiers, prop names and types untouched (`series` пропы, `xKey` өрісі). The chart names
follow the library's own Kazakh `chartNames` (`@startupjafari/charts-core` messages), so a page
title matches what the chart announces to screen readers. Where StudentHub's Kazakh catalogue
already has a term for the same interface concept, the site uses it (Баптаулар, Көшіру,
Жүктелуде…, Деректер жоқ, Ашық / Күңгірт / Жүйелік, Басты бет, Бет табылмады).

## Left in English on purpose

- Example source code and the texts it renders (it is the real code shown in the code panels).
- `CHANGELOG.md` (the Russian and Kazakh pages show a note above it).
- Benchmark data identifiers that have no translation (unknown scenario names fall back to the
  English text from `benchmarks/*.json`).

## Adding another language

Add it to `Lang` and `LANGS` in `src/i18n/lang.ts`, to `same()` and `isLang()`; TypeScript then
lists every `L<…>` value and dictionary that needs a translation (Kazakh was added this way).
Add its dictionary (with `langName`, its own name for the language select) to `MESSAGES` in
`src/i18n/index.ts`, an entry with its flag to `LANGUAGES` in `src/shell/controls.tsx`, and a
plural helper if the language needs one. The router picks up the `#/<lang>` prefix from `LANGS`;
extend `browserLang()` for detection. Check that the chart library has locale data for it
(`MESSAGES` and `resolveFormatLocale` in `packages/core/src/formatting`); without it, charts
fall back to English texts.
